# Agent parity workflow

Claude Code, Codex, and Cursor form one repository toolchain. A change to one enabled harness's rules, skills,
hooks, or docs includes its partners in the same change.

Adapters:

- [Claude Code rule](../../.claude/rules/agent-parity.md)
- [Codex/Cursor skill](../../.agents/skills/agent-parity/SKILL.md)
- [Cursor rule](../../.cursor/rules/agent-parity.mdc)

## Model

| Surface | Source of truth | Harness adapters |
|---|---|---|
| Policy | `docs/workflows/*.md`, root/nested `AGENTS.md` | Link only |
| Skill | Canonical workflow | `.claude/skills`, `.agents/skills` |
| Path rule | `.claude/rules/*.md` (tool-neutral body) | `.agents/skills` adapter for Codex/Cursor; `.cursor/rules/*.mdc` generated by `scripts/gen-cursor-rules.mjs` |
| Rule index | `.claude/rules/INDEX.md` (human index: scope, workflow, trigger per rule) | None; not a rule |
| Hook logic | `scripts/hooks/*.mjs` | Three native JSON configs |
| Enforcement | `scripts/check-docs.mjs`, `scripts/check-sdd.mjs` | Git hook + CI invocation |

## Partner rules

1. `.claude/skills/<name>` and `.agents/skills/<name>` move together.
2. `.claude/rules/<name>.md` and `.cursor/rules/<name>.mdc` move together.
3. Hook configs (`.claude/settings.json`, `.codex/hooks.json`, `.cursor/hooks.json`) move together: a change
   to one includes every other enabled config, or names a concrete parity exception. The shared script under
   `scripts/hooks/` may change alone.
4. Adapter links one canonical workflow; workflow links every adapter. A link to `.claude/rules/<name>.md`
   also covers its generated `.cursor/rules/<name>.mdc`.
5. Native-only metadata stays native and records a concrete parity exception when changed alone.
6. Post-edit hooks are reminders, not pre-edit policy enforcement.
7. Path-scoped concern = Claude rule + `.agents/skills` adapter; invocable workflow = skill in `.claude/skills` and
   `.agents/skills`. Never both a rule and a skill for one concern.
8. Every `.agents/skills/<name>` carries `agents/openai.yaml` (Codex display metadata).
9. `.cursor/rules/<name>.mdc` is generated from `.claude/rules/<name>.md`: edit the source, run
   `node scripts/gen-cursor-rules.mjs`, commit both. Never hand-edit `.mdc`; the gate runs `--check`.
10. `.claude/rules/INDEX.md` is the human index of the rules, not a rule: no mirror, no `.agents` twin, no parity
    partner. Adding, removing, or renaming a rule updates the index in the same change.

## Adapter shape

- The rule's `description` is its one-line trigger: what situation loads it and what it demands.
- The rule body is one paragraph: "Adapter, path matching only (<scope>). The rules, the why, and the how to apply
  live in <workflow>. Read it before editing." Link a section of the workflow when the workflow covers several
  concerns.
- A rule without `paths` loads for every task; use it only for a workflow-ordering guard.
- The file name describes the scope of the rule, not the incident that produced it.
- Every workflow keeps its **Why** and **How to apply** sections. The why cites the real incident: a rule justified
  by an invented example cannot be checked, so it cannot be maintained. A rule stripped to its assertion gets
  deleted the first time it is inconvenient.
- A rule body carries no tool-specific tokens (`Skill("...")`, "Claude-specific"): the generator refuses them,
  because the Cursor mirror copies the body verbatim.

Run `node scripts/check-sdd.mjs` before handoff. A green shape check cannot prove adapter prose has matching
semantics, so keep adapters thin.
